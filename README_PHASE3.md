# A-Hako v51 — Distribution Observation Phase 3

## Purpose
Observe how an issued Distribution.scene travels without copy protection or buyer tracking.

## Identity model
- `workId`: the work identity.
- `distribution.copyId`: one officially issued copy.
- `observerId`: anonymous ID generated by Local Player **per copyId and browser profile**.
  - It is not shared across different copyIds.
  - It is not a user/account/buyer/device-global identifier.
- `sessionId`: random ID per opened .scene session.

## Consent
Observation is never silently enabled.
On the first Distribution.scene opened in Local Player, the reader chooses:
- OK: allow anonymous observation
- Cancel: read offline without observation

The choice is saved in Local Player localStorage.
Master.scene has no copyId and is never observed by this mechanism.

## Sent to API
Only:
- event: start / progress / complete
- workId
- copyId
- copy-specific observerId
- sessionId
- sceneCount
- current scene index

Not sent:
- filename
- file URL/path
- title
- body text
- author name
- buyer/order/account information

## Counting semantics
`観測読者+` is **not a verified human count**.
It means unique `(copyId, observerId)` pairs observed in the selected period.
The same person on multiple browsers/devices can appear more than once; offline/non-consenting reading is not observed.
The `+` is intentional.

## Worker endpoints
- `POST /distribution-observation`
- `GET /admin/distribution-observation?days=7` (ADMIN_TOKEN required)

R2 key layout:
`distribution-observation/YYYY-MM-DD/workId/copyId/observerId.json`

## Admin dashboard
Adds `DISTRIBUTION NOW / 配布版の観測` with:
- today observed readers+
- today completions
- 7-day observed readers+
- observed copies
- observed works
- 7-day opens
- top traveling copies (copyId)
- work-level summary

## Deliberately NOT implemented yet
- relayId / parentRelayId
- official RELAY action
- buyer identification
- piracy accusations / automatic enforcement
- DRM
- cross-copy observer tracking
